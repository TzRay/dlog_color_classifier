# DJI Color Classifier v1.0 开发规格

## 1. 项目定位

DJI Color Classifier v1.0 是一个跨平台开源桌面工具和命令行工具，用于读取 DJI 视频文件中的私有 `djmd` 元数据与 QuickTime 标签，识别素材色彩模式，并按用户选择执行分类整理。

v1.0 的核心目标是：

- 不强制依赖 `ffmpeg` 或 `ffprobe`。
- 支持 Windows 和 macOS 普通用户直接使用。
- 同时提供 CLI 和 GUI。
- 支持识别、重命名、移动、复制、导出报告和撤销。
- 对文件操作默认保守，所有实际修改必须可预演、可追踪、可回滚。

## 2. 目标用户

### 2.1 剪辑用户

用户拥有一批 DJI 素材，希望快速区分 `D-Log`、`D-Log2`、普通 `709`、`Rec.2100 HLG`，并将素材分目录整理到剪辑工程中。

### 2.2 批处理用户

用户熟悉命令行，希望将本工具接入素材导入脚本、NAS 整理流程或自动化工作流。

### 2.3 开源贡献者

贡献者希望补充更多 DJI 机型、固件、容器结构样本，并能通过测试验证改动没有破坏已有识别规则。

## 3. v1.0 范围

### 3.1 必须支持

- 原生解析常规 MP4/MOV 容器，读取 DJI `djmd` 轨第一包及 QuickTime `mdta` 色彩标签。
- 识别 `D-Log`、`D-Log2`、普通 `709`、`Rec.2100 HLG`、无法确认。
- 扫描单个目录。
- 可选递归扫描子目录。
- 支持 `.mp4`、`.mov`、`.m4v`，大小写不敏感。
- CLI 批处理。
- PySide6 GUI。
- 预演模式。
- 执行模式。
- 操作清单 `manifest.json`。
- 基于 `manifest.json` 的撤销。
- CSV 和 JSON 报告导出。
- Windows exe 打包。
- macOS 可执行程序或 `.app` 打包。
- 单元测试和核心集成测试。
- 中文界面和中文日志，必要技术字段可中英结合。

### 3.2 v1.0 不承诺支持

- 解析视频画面内容。
- 解码 H.264/H.265。
- 修改视频文件内部元数据。
- 云同步。
- 自动上传样本。
- 完整支持所有 fragmented MP4。
- 保证覆盖所有 DJI 机型和所有固件。
- Linux GUI 发布包。Linux 可以保留源码运行和测试支持。

## 4. 识别规则

### 4.1 当前规则

按证据可靠性依次判定：

- QuickTime `com.dji.camera.ColorGammaSxS` 为已知文本标签时优先使用；
- `djmd` 的 `ColorGammaSxS == 22`：`D-Log2`；
- `djmd` 的 `ColorGammaSxS == 2`：`D-Log`；
- 枚举缺失且 `record_mode == 8`：普通 `709` 兼容规则；
- 明确标签与已映射枚举冲突，或无可用证据：无法确认。

### 4.2 证据输出

每个识别结果必须保留证据字段：

- 文件路径
- 文件大小
- 容器类型
- 是否找到 `djmd` track
- `ColorGammaSxS` 原始值
- `record_mode` 原始值
- 读取方式：`native`
- 失败原因，若有

示例：

```json
{
  "path": "D:/media/DJI_0001.MP4",
  "mode": "D-Log2",
  "color_gamma_sxs": 22,
  "record_mode": null,
  "reader": "native",
  "evidence": "djmd: top2.top2.top3.field1=22; top2.top3.field5=null"
}
```

## 5. 文件整理模式

v1.0 必须支持以下操作模式。

### 5.1 只识别

不修改任何文件，仅展示和导出结果。

CLI 示例：

```powershell
dji-color scan "D:\media" --output result.csv
```

### 5.2 添加前缀

根据色彩模式给文件名添加前缀。

默认前缀：

- `D-Log`：`dlog_`
- `D-Log2`：`dlog2_`
- 普通 `709`：不添加前缀
- `Rec.2100 HLG`：不添加前缀
- 无法确认：不添加前缀

CLI 示例：

```powershell
dji-color organize "D:\media" --mode prefix
dji-color organize "D:\media" --mode prefix --apply
```

### 5.3 移动到分类目录

根据色彩模式将视频移动到分类目录。

默认目录：

- `D-Log`：`dlog/`
- `D-Log2`：`dlog2/`
- 普通 `709`：`rec709/`
- `Rec.2100 HLG`：`hlg/`
- 无法确认：`unknown/`

CLI 示例：

```powershell
dji-color organize "D:\media" --mode move --apply
```

### 5.4 复制到分类目录

与移动模式类似，但保留原始文件。

CLI 示例：

```powershell
dji-color organize "D:\media" --mode copy --apply
```

### 5.5 自定义模板

v1.0 支持基础命名模板：

- `{original}`：原文件名
- `{stem}`：无扩展名文件名
- `{suffix}`：扩展名
- `{mode}`：规范化模式名，值为 `dlog`、`dlog2`、`rec709`、`rec2100_hlg`、`unknown`
- `{mode_label}`：显示名，值为 `D-Log`、`D-Log2`、`普通709`、`Rec.2100 HLG（HDR）`、`无法确认`

示例：

```powershell
dji-color organize "D:\media" --mode prefix --name-template "{mode}_{original}"
```

目录模板 v1.0 支持：

```powershell
dji-color organize "D:\media" --mode move --dir-template "{mode}"
```

## 6. 安全策略

### 6.1 默认预演

所有会修改文件系统的命令默认只生成计划，不执行修改。

必须显式传入：

```powershell
--apply
```

才允许重命名、移动或复制。

### 6.2 冲突策略

目标文件已存在时，支持三种策略：

- `error`：默认，报错并停止执行。
- `skip`：跳过冲突文件。
- `suffix`：自动追加序号，例如 `DJI_0001_001.MP4`。

CLI 参数：

```powershell
--on-conflict error
--on-conflict skip
--on-conflict suffix
```

### 6.3 Manifest

每次执行必须生成 `manifest.json`，记录：

- 工具版本
- 执行时间
- 操作模式
- 扫描根目录
- 每个文件的原路径
- 每个文件的目标路径
- 操作类型
- 识别结果
- 执行结果
- 错误信息

默认保存位置：

```text
<scan-root>/.dji-color-classifier/manifests/<timestamp>.json
```

### 6.4 Undo

撤销命令通过 manifest 执行。

CLI 示例：

```powershell
dji-color undo "D:\media\.dji-color-classifier\manifests\2026-06-29T231500.json"
```

撤销规则：

- `rename`：将目标路径改回原路径。
- `move`：将目标路径移回原路径。
- `copy`：删除复制出来的目标文件，但必须确认目标文件仍匹配 manifest 中记录的文件大小和可选 hash。

## 7. 原生 MP4 读取器规格

### 7.1 目标

实现轻量级 ISO BMFF/MP4 box 解析器，只为读取 DJI `djmd` 第一包数据服务。

不实现完整媒体解码器。

### 7.2 必须解析的 box

顶层和嵌套 box：

- `ftyp`
- `moov`
- `trak`
- `tkhd`
- `mdia`
- `hdlr`
- `minf`
- `stbl`
- `stsd`
- `stsz`
- `stz2`
- `stsc`
- `stco`
- `co64`
- `mdat`

### 7.3 Track 定位

优先通过 `stsd` sample entry 类型识别 `djmd` track。

辅助证据：

- `hdlr.handler_type`
- track id
- sample table 完整性

### 7.4 第一包定位

读取 `djmd` track 的第一个 sample：

1. 从 `stsz` 或 `stz2` 读取 sample size。
2. 从 `stsc` 读取 sample 到 chunk 的映射。
3. 从 `stco` 或 `co64` 读取 chunk offset。
4. 计算第一个 sample 的文件偏移。
5. 从文件中读取对应长度的 bytes。

### 7.5 必须支持的 MP4 细节

- 32 位 box size。
- `size == 1` 的 64 位 largesize。
- `size == 0` 的延伸到文件末尾 box。
- 大文件偏移 `co64`。
- 未知 box 跳过。
- 不一次性读取完整视频文件。

### 7.6 暂不支持处理

如果检测到以下结构，v1.0 可以给出明确错误：

- `moof`
- `traf`
- `trun`
- sample table 缺失
- 加密或非常规封装导致无法定位 sample

错误示例：

```text
暂不支持 fragmented MP4：检测到 moof/traf/trun，无法原生读取 djmd 第一包。
```

## 8. Protobuf 解析器规格

继续保留未知 schema 解析方式。

必须支持：

- varint
- fixed32
- fixed64
- length-delimited
- 有限深度递归
- 非法数据安全退出

默认最大递归深度：

```text
8
```

当解析失败时，不应导致整个批任务崩溃。应将该文件标记为失败，并记录错误原因。

## 9. CLI 规格

统一入口：

```powershell
dji-color
```

### 9.1 子命令

```powershell
dji-color scan <directory>
dji-color organize <directory>
dji-color undo <manifest>
dji-color version
```

### 9.2 scan

参数：

- `<directory>`：扫描目录。
- `--recursive`：递归扫描。
- `--output <path>`：输出路径。
- `--format csv|json`：输出格式，默认 `csv`。
- `--include-unknown`：报告中包含无法确认文件，默认包含。
- `--quiet`：减少输出。
- `--verbose`：输出详细诊断。

### 9.3 organize

参数：

- `<directory>`：扫描目录。
- `--recursive`：递归扫描。
- `--mode prefix|move|copy`：整理模式。
- `--apply`：执行修改。
- `--name-template <template>`：命名模板。
- `--dir-template <template>`：目录模板。
- `--on-conflict error|skip|suffix`：冲突策略。
- `--with-sidecars`：同时处理同 basename 的伴随文件。
- `--manifest-dir <path>`：manifest 输出目录。
- `--report <path>`：同时输出报告。
- `--format csv|json`：报告格式。
- `--quiet`
- `--verbose`

### 9.4 undo

参数：

- `<manifest>`：需要撤销的 manifest。
- `--apply`：默认预演撤销，传入后真正执行。
- `--on-missing skip|error`：原文件或目标文件缺失时的策略。

```text
dji_color_classifier/

  test_executor.py
  test_manifest.py
specs/
  v1.0-development-spec.md
```

### 11.1 models.py

核心数据结构：

- `ColorMode`
- `ScanResult`
- `PlanAction`
- `PlanItem`
- `ExecutionResult`
- `Manifest`

建议使用 `dataclass`，保持轻量和易测试。

### 11.2 classifier.py

只负责把 `djmd` bytes 转为色彩模式结果。

禁止在该模块内读写文件系统。

### 11.3 scanner.py

负责：

- 枚举视频文件。
- 调用 reader。
- 调用 classifier。
- 聚合结果。
- 捕获单文件异常。

### 11.4 planner.py

负责从扫描结果生成操作计划。

禁止执行实际文件修改。

### 11.5 executor.py

负责执行计划。

必须：

- 逐项执行。
- 捕获错误。
- 写入执行结果。
- 不覆盖用户文件。

### 11.6 gui

GUI 只能调用核心服务，不直接实现识别规则、MP4 解析或文件操作策略。

## 12. 日志和错误信息

日志默认中文。

允许技术字段中英结合，例如：

```text
未找到 DJI djmd 数据轨：DJI_0001.MP4
暂不支持 fragmented MP4：检测到 moof box
读取 sample table 失败：缺少 stsz/stz2
```

日志级别：

- `DEBUG`：box 解析、字段路径、内部诊断。
- `INFO`：扫描进度、计划摘要、执行结果。
- `WARNING`：跳过文件、无法确认。
- `ERROR`：单文件失败、manifest 写入失败。

GUI 日志面板默认显示 `INFO` 以上。

CLI 默认显示简洁摘要，`--verbose` 显示详细日志。

## 18. 主要风险

### 18.1 MP4 结构兼容风险

不同 DJI 设备可能使用不同 box 结构。

应对：

- 明确错误信息。
- 收集样本。
- fixture 化。
- 在文档中维护兼容矩阵。

### 18.2 误移动或误改名风险

文件整理工具最怕误操作。

应对：

- 默认预演。
- manifest。
- undo。
- 冲突默认停止。
- GUI 执行前确认。

### 18.3 GUI 打包体积

PySide6 打包体积较大。

应对：

- CLI 和 GUI 分开发布。
- README 明确两个版本用途。

### 18.4 macOS 签名和 Gatekeeper

未签名应用可能被 macOS 拦截。

应对：

- v1.0 文档说明打开方式。
- 后续评估签名和 notarization。
